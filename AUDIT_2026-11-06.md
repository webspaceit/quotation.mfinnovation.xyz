## 1. Executive summary

The application is functionally sound and lint-clean (32 PHP files, 0 syntax errors on PHP 8.5). It is, however, **not safe to expose on the internet in its current state**, for one specific reason: the web root contains a set of leftover operational scripts that an anonymous visitor can call.

Three things outrank everything else:

1. **`fix_password.php` resets the admin password to `admin123` on any anonymous GET.** Anyone who can reach the URL owns the system.
2. **`install.php`, `add_cols2.php`, `fix_top_save.php`, `fix_revert_top.php`, `check_top2.php`** are publicly reachable and perform DB creation, schema alteration, and file writes with no authentication.
3. **`ajax/send_email.php` has no authentication check.** It is protected only by a CSRF token, and a valid token is handed to anonymous visitors on the login page — so it is effectively an open mail relay through your SMTP account.

Separately, `.env` and `database.sql` sit in the web root with no deny rule in `.htaccess`.

Everything else (bugs, print/PDF layout, feature gaps) is real but secondary. The full picture is below, with a phased plan at the end.

**Grounded state of the system:** DB `qms_db` is live — 1 user, 1 client, 1 quotation (`QT-2026-0001`, draft, ৳46,200), 5 line items, 0 email logs. No `.git` repository.

## 3. Security findings

### 3.1 Critical

| # | Issue | Location | Impact | Fix |
|---|---|---|---|---|
| S1 | Public password reset — any GET rewrites the admin password to `admin123` and prints the new hash | `fix_password.php:4-5` | Full account takeover | Delete the file. Replace with an authenticated "Change password" feature. |
| S2 | Public installer — hardcoded `root` / empty password, recreates database and reports error text | `install.php:3-19` | Schema reset / DB disclosure; hardcoded credentials | Delete; install via phpMyAdmin or a one-time CLI script outside the web root |
| S3 | Public maintenance scripts — live `ALTER TABLE`, `file_put_contents()` on `admin/settings/index.php`, and source disclosure of that file | `add_cols2.php:14`, `fix_top_save.php:21`, `fix_revert_top.php:19`, `check_top2.php:3`, `check_bottombtn.php:2` | Remote schema change, remote file modification, source/theft of settings code | Delete all five. Migrations belong in a `database/migrations/` folder run from CLI. |
| S4 | `ajax/send_email.php` performs **no authentication check** — only `verify_csrf()` | `ajax/send_email.php:2-14` | Open relay: anonymous visitor loads `login.php`, reads the CSRF field issued for their anonymous session (since `csrf_token()` is generated pre-login), then POSTs arbitrary `to_email` / `subject` / `message` and mails through your SMTP account. Also writes `email_logs` and flips quotation status to `sent`. | Add `require auth` + `isLoggedIn()` check before anything else; validate the quotation belongs to the caller's scope |

### 3.2 High

| # | Issue | Location | Impact | Fix |
|---|---|---|---|---|
| S5 | `.env` and `database.sql` are in the web root; `.htaccess` has no deny rule for them | `.htaccess:1-7` | DB credentials and full schema downloadable if Apache serves dotfiles | Add `<FilesMatch "^\.">` + explicit deny for `database.sql`, `AUDIT*.md`, `README.md`; better, move `.env` above `public_html` |
| S6 | Settings page has **no admin-role guard** — any `staff` user can edit company data and SMTP credentials | `admin/settings/index.php:1-56` (compare the correct guard at `admin/users/index.php:6`) | Privilege escalation to email/identity control; staff can redirect outgoing quotations | Add the same admin check used in `admin/users/index.php` |
| S7 | SMTP password stored in plaintext and echoed back into the HTML form | `admin/settings/index.php:209` | Anyone with page access or a cached page sees the credential; DB dump leaks it | Encrypt at rest (`sodium`/`openssl` with key from `.env`); render as masked placeholder, only update when a new value is submitted |
| S8 | No brute-force protection on login | `login.php:10-18`, `classes/User.php:9-20` | Unlimited password guessing | Per-IP + per-account attempt counter with lockout/backoff |

### 3.3 Medium

| # | Issue | Location | Impact | Fix |
|---|---|---|---|---|
| S9 | DB connection failure prints `$e->getMessage()` and dies | `classes/Database.php:19` | Leaks host, user, and driver detail | Log internally, show generic error page |
| S10 | Upload validation is extension-only — no `getimagesize()`, no MIME check, no `uploads/.htaccess` | `includes/functions.php:39-56` | Image-polyglot uploads; `assets/uploads/` has no execution guard and `mkdir(0777)` | Add `finfo`/`getimagesize` check, force `0644`, add `php_flag engine off` in `assets/uploads/.htaccess` |
| S11 | CSRF compare uses `!==` not `hash_equals()`, token never rotates, and `verify_csrf()` dies with a plain-text body | `includes/functions.php:13-19` | Timing-leak (minor), token reuse for session lifetime, AJAX handlers return non-JSON on rejection | `hash_equals()`, rotate after sensitive actions, return JSON 419 for AJAX |
| S12 | State-changing operation via GET without CSRF — duplicating a quotation | `admin/quotations/duplicate.php:5` | Link prefetchers/scanners create duplicate records | Convert to POST + `verify_csrf()` |
| S13 | Session cookie hardening absent (`HttpOnly`, `SameSite`, `Secure`) | `config/database.php:68` | Session theft via XSS/CSRF surface | Set `session_set_cookie_params(['httponly'=>true,'samesite'=>'Lax','secure'=>…])` before `session_start()` |
| S14 | Email headers partly unvalidated (`$to`, `$cc`, `$bcc`, `$subject` from POST); `mail()` fallback path is injectable | `ajax/send_email.php:26-31, 80-88` | Header injection when PHPMailer is absent (it currently is) | `filter_var(..., FILTER_VALIDATE_EMAIL)`, strip CR/LF from subject |

### 3.4 Low

- No password policy — users can be created with a single character (`classes/User.php:41-47`).
- No self-service password change, no user edit/disable/delete — only create (`admin/users/index.php`).
- `email_logs` stores the full message body indefinitely, including client PII.
- `User::create()` does not pre-check duplicate email → uncaught `PDOException` → blank 500 (`admin/users/index.php:16`).

## 6. Feature gaps

Not defects — deliberate scope limits, listed because they are the natural next increments.

**Sales workflow**
- Discount (% or flat) — only tax exists today
- Per-item UOM ("1 year", "5 pages") and a reusable item/service catalog
- Quotation revisions with history (client asked for v2 — currently overwrites)
- Convert accepted quotation → invoice / proforma / work order
- Online accept/reject link for the client (tokenised, no login)
- Auto-expiry job that flips `valid_until` past dates to `expired`

**Output**
- Real PDF (see Phase 2)
- CSV/Excel export of quotations and clients
- Per-quotation currency override (currently one global symbol)

**Data & ops**
- Server-side search + pagination on quotations/clients
- Delete/archive with soft-delete (`deleted_at`) instead of hard delete
- Activity/audit log (who changed what, when)
- Email log viewer (the table exists and is written to, but has no UI)
- Backup/restore helper

**Access**
- Self-service password change (replaces `fix_password.php`)
- User edit/disable/reset by admin
- Password policy + optional 2FA

**Reporting**
- Win rate trend by month, conversion by client, average deal size, ageing of sent quotes

## 7. Proposed plan

Ordered by risk reduction per hour. Estimates assume I do the work; they are my working numbers, not commitments.

### Phase 0 — Make it safe to deploy (~2 h, highest value)
1. Delete the 8 root scripts (`install.php`, `sample.php`, `fix_password.php`, `add_cols2.php`, `fix_top_save.php`, `fix_revert_top.php`, `check_top2.php`, `check_bottombtn.php`). Keep `database.sql` but deny it over HTTP.
2. Harden `.htaccess`: deny dotfiles, `*.sql`, `*.md`; add `assets/uploads/.htaccess` with engine off.
3. Add authentication to `ajax/send_email.php` + validate recipient addresses + strip CR/LF from subject.
4. Add the admin-role guard to `admin/settings/index.php`.
5. Session cookie flags (`HttpOnly`, `SameSite=Lax`, `Secure` when HTTPS) before `session_start()`.
6. `git init` + `.gitignore` (`.env`, `assets/uploads/*`) + baseline commit, so every later change is reversible.

### Phase 1 — Data integrity (~half day)
7. Wrap create/update in `beginTransaction`/`commit`/`rollBack`; move item deletion in `edit.php` inside the transaction.
8. Atomic quotation numbering (`SELECT ... FOR UPDATE` or a counter table with `UPDATE ... SET n = n+1`).
9. Fix B5, B9, B10, B15 (cheap, visible).
10. Upload validation via `finfo` + `getimagesize`.
11. Login throttling.

### Phase 2 — Customer-facing output (~1 day)
12. Rewrite the print stylesheet: remove the `tfoot` row-group rule, reserve footer space, add `page-break-inside: avoid`, `overflow-wrap`, `@page` counters.
13. Scope typography settings to the table only.
14. **Real PDF**: either
    - (a) vendor a single-file library such as TCPDF/FPDF into `vendor/` (no Composer, matches current architecture), or
    - (b) keep browser "Print → Save as PDF" and stop claiming PDF attachments, sending a self-contained inline-CSS HTML instead.
    Recommendation: (a) — buyers expect a PDF attachment.

### Phase 3 — List UX (~1 day)
15. Pagination + server-side search on quotations and clients; wire the header search box.
16. Delete/archive with soft-delete + confirmation.
17. Email log viewer; quotation activity log.

### Phase 4 — Commercial features (~2-3 days, choose from §6)
18. Discount, UOM, item catalog, per-quotation currency.
19. Quotation revisions with history.
20. CSV export; reporting dashboard (win-rate trend, conversion by client).

## 8. Decisions I need before writing code

1. **Deployment target** — shared hosting on cPanel, or this WAMP box only? This decides how aggressive the `.htaccess`/PHP-version assumptions can be, and whether `vendor/` libraries are acceptable.
2. **Multi-user?** If it is effectively a single admin today, I would skip several role/permission items and cut Phase 0 to about an hour.
3. **PDF library** — may I add a vendored library under `vendor/` (no Composer), or must everything stay dependency-free?
4. **Priority for Phase 4** — discount/UOM, revisions, exports, or reporting? Pick one; I would do them sequentially rather than all at once.
